Editor & Designer Handbook

How this site is put together, what you can change, and how to ask for what you can't.

Two addresses, two jobs

control.yukisrescue.org

Where you work. This WordPress. Only the four of us can reach it. Nothing you do here is visible to the public until you publish.

www.yukisrescue.org

What the public sees. A copy of this site, saved as plain files. It has no WordPress in it at all — which is why some things behave differently. See What doesn't work live below.

Signing in

Two doors, one after the other. They are different systems with different credentials, which catches everyone out once.

  1. Cloudflare. Enter your email, receive a one-time code, paste it back. This keeps the internet out. You stay signed in for 24 hours.
  2. WordPress. Your normal username and password. Change it under Users → Profile if you haven't yet.

If you get stuck, say which door refused you. It changes the answer completely. Note that "Lost your password?" does not work here — this site cannot send email, so Mario resets it.

What you can do

  • Write and edit every page, including each other's. Nothing is locked to one person.
  • Change how the site looks — Appearance → Editor. Colours, fonts, spacing, layout, and the header and footer. The palette is preloaded with the site's colours, so picking from the swatches keeps everything consistent.
  • Add pages and menus. New pages are picked up automatically — no configuration, nobody to tell.
  • Upload images. Please resize large photos first; a picture straight off a phone can be several megabytes, which is slow for anyone on a poor connection.
  • Publish to the live site, on your own, without approval.

Publishing, and the thing worth knowing

Settings → Simply Static → Generate Static Files. The live site updates about a minute later, by itself.

There is no preview and no review step. What you publish is public immediately. Mario can undo any publish in about a minute — so if something goes wrong, say so straight away rather than trying to fix it under pressure.

What you can't do, and why

You cannot install or activate plugins, switch or edit themes, change site settings, or add users. That isn't a lack of trust — it's what makes it safe to let you publish without anyone checking first. None of those actions can be undone by reverting a page.

Plugins: how it actually works

The most common question, so plainly:

  • There is no personal or per-account plugin. This is a single WordPress site, not a network of sites. A plugin is either installed and active for the whole site and everyone on it, or it isn't installed at all. Nothing can be enabled "just for me".
  • Only an administrator can install or activate one. That's Mario. Editors — all three of you — cannot, by design.
  • Every plugin affects everyone. Because it is site-wide, one person's plugin choice changes the site for the other two and for every visitor.

Asking for one

Ask Mario, and include: what you're trying to achieve (not just the plugin name), a link to it, and whether a visitor needs to interact with it or whether it only helps you while editing. That last point decides whether it can work at all.

What doesn't work on the live site

This is the part that surprises people, and it's worth understanding once rather than being caught by it repeatedly.

The public site is a set of plain saved files. There is no WordPress running behind it. So anything that needs WordPress to do something when a visitor clicks will look fine and quietly fail.

The test: does it need to run something on the server when a visitor uses it? If yes, it won't work live.

Won't work live

  • Contact or signup forms from a plugin
  • Comments
  • Site search
  • Logins, memberships, anything personalised per visitor
  • Anything counting or storing what visitors do

Works fine live

  • Every layout, styling and typography plugin
  • Block libraries and page builders
  • Image and gallery tools
  • SEO and metadata plugins
  • Anything from an outside service that embeds its own code — donation widgets, video, maps, social feeds

A live example: Constant Contact Forms

The Constant Contact Forms plugin is installed. Its forms will not work on the public site. They post back to WordPress to be processed, and there is no WordPress on the live site — so a visitor fills the form in, presses send, and nothing reaches Constant Contact.

Use it inside WordPress by all means. For the public site, use Constant Contact's own hosted signup form — either a button linking to it, or their embed code, which talks to their servers directly and works anywhere.

The Feedback page's contact form is built differently for exactly this reason: it sends to a small service of our own rather than to WordPress. It's the only form on the site that works live.

When something's wrong

  • A change isn't showing live. Did you click Generate Static Files after saving? That's nearly always it. If you did, wait two minutes and hard-refresh.
  • A form doesn't do anything on the live site. Expected, if it came from a plugin. See above.
  • Something looks broken publicly. Tell Mario immediately. Undoing takes about a minute. Don't try to fix it by publishing repeatedly.
  • A page you made is missing from the live site. This shouldn't happen — it's handled automatically. Say so if it does, because it means something is wrong beyond your change.
